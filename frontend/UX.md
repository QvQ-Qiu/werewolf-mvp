# 对局与复盘 · 产品需求分析（v2）

## 1. 问题陈述

| 痛点 | 现状 | 影响 |
|------|------|------|
| 空间浪费 | 圆桌环 + 右侧日志分栏，移动端纵向堆叠 | 看座位要滚、看公屏也要滚，无法同时掌握局势 |
| 信息割裂 | 存活状态与发言历史不在同一视口 | 推理时需频繁切换注意力，手机体验差 |
| 思考链扁平 | 复盘「AI 思考链」按时间平铺 | 难以回答「这个 AI 整局怎么想的」，不符合死后钻取需求 |

## 2. 用户与场景

- **主用户**：手机端玩家，边听/边看 AI 发言边扫座位存活
- **次要场景**：死后观战、局后复盘某 AI 的策略链

## 3. 设计目标

1. **一屏双读**：同一视口内同时看到「谁还活着」与「公屏发生了什么」
2. **拇指友好**：操作区贴底，不遮挡公屏主体
3. **复盘按人归并**：默认总览时间线；个体档案按座位聚合策略/思考/行动

## 4. 对局页布局（三列棋盘）

```
┌────────────────────────────────────────┐
│ 顶栏：阶段 · 日/夜 · 连接 · 你的身份      │  固定高度
├──────┬─────────────────────┬───────────┤
│ 1    │                     │ 6         │
│ 2    │    公屏信息流         │ 7         │  flex-1 可滚动
│ 3    │    （发言/系统/票型）  │ 8         │
│ 4    │                     │ 9         │
│ 5    │                     │ 10        │
├──────┴─────────────────────┴───────────┤
│ 操作坞（发言/投票/夜晚 · 仅需要时出现）   │  贴底
└────────────────────────────────────────┘
```

- **左列**：1～5 号，窄列头像（号码 + 存活态）
- **右列**：6～10 号，同上
- **中间**：公屏日志，占最大宽度，纵向滚动
- **桌面**：列宽略增，中间 min-width 320px
- **手机**：左右列各 ~52px，中间自适应；整页 `100dvh` 不整页滚动

## 5. 座位头像交互

| 状态 | 视觉 |
|------|------|
| 存活 | 细边框 + 号码 |
| 出局 | 降透明度 + 删除线号码 |
| 你的座位 | 暖色描边 |
| 正在发言 | 高亮描边 |
| 投票期可点 | 可点击，选中态加深边框 |

点击座位 = 投票预选（与操作坞「确认投票」联动）。

## 6. 操作坞交互流程

```
阶段推进 → 系统广播 PHASE / PUBLIC_LOG
    ↓
子阶段 = 发言 → 轮到你时操作坞弹出 textarea + 倒计时
子阶段 = 投票 → 点头像预选 + 操作坞确认/弃票
子阶段 = 夜晚私域 → 操作坞展示技能面板（仅本人）
    ↓
出局 → 操作坞隐藏，公屏 + 座位仍可看（观战）
```

## 7. 复盘页信息架构

### 7.1 总览（默认 Tab）

- 公屏时间线，与对局页中间栏同构，便于回忆局内体验

### 7.2 个体档案（按人归并）

```
左侧/顶部：10 人座位列表（selector）
右侧/主体：选中者的档案
  ├─ 身份 · 人格 · 存活
  └─ 按回合折叠的时间线
        ├─ 策略选择
        ├─ 内心思考
        ├─ 行动（刀/验/票）
        └─ 公开发言
```

- 数据模型：`PlayerDossier.entries[]` 已按 `seat` 归并，UI 按 `roundOrder` 分组展示
- 后续接 API：`GET /games/{id}/replay` 返回 dossiers 数组即可

## 8. 非目标（本版不做）

- 3D 圆桌 / 写实头像
- 公屏插话、自由聊天
- 存活时偷看他人思考链（对局页）

## 9. 验收标准

- [ ] 手机竖屏：不滚动页面即可同时看到 10 人存活态 + 至少 3 条公屏消息
- [ ] 投票：点头像后操作坞显示已选座位
- [ ] 复盘：可切换任意 AI 查看其完整思考链，且存在总览 Tab
